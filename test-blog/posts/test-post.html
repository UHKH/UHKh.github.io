测试博文：写下并发布第一篇 ​

这是一篇测试博文。它存在的意义不是讲什么大道理，而是把「写 → 构建 → 发布 → 打开」这条链路整条跑通一遍。

为什么先写一篇测试文 ​

搭博客最容易踩的坑，是把精力全花在选主题、配插件上，结果一个字没写。 所以这里反着来：先把一篇真实的文章写出来、发出去、能打开，剩下的慢慢调。

这篇测试文要验证四件事：

  1. Markdown 渲染是否正常（标题、列表、表格、代码块、提示容器）
  2. 构建产物能否独立部署（不依赖本地开发服务器）
  3. 链接、导航、侧边栏的路径是否正确
  4. 部署到线上后，资源路径（base）有没有配错

写作长什么样 ​

一句话：你写 Markdown，VitePress 负责把它变成网站。

bash
# 本地写作：起开发服务器，改完即刷新
npm run docs:dev

# 构建：产出纯静态文件到 docs/.vitepress/dist
npm run docs:build

# 本地预览构建产物（接近线上真实效果）
npm run docs:preview

几个常见元素的样子 ​

普通表格：

环节命令产物
开发npm run docs:dev本地热更新服务
构建npm run docs:builddocs/.vitepress/dist
预览npm run docs:preview本地静态服务

代码高亮：

js
// 配置里的 base 决定了部署路径，配错了就会白屏或者 404
const base = process.env.BLOG_BASE || '/'
export default defineConfig({ base })

提示

base 一定要以 / 开头、以 / 结尾。部署到子目录时写成 /test-blog/。

注意

构建产物是静态文件，不包含任何服务端逻辑。要评论、搜索、访问统计，得另外接第三方服务。

关于「发布」这件事 ​

静态博客的发布，说到底就是把 dist 目录里的文件放到一个能被公网访问的地方。常见几种：

  • GitHub Pages —— 免费，和仓库绑定，推上去就自动构建
  • Netlify / Vercel / Cloudflare Pages —— 免费额度够用，支持自动构建
  • 对象存储 + CDN —— 国内访问速度通常更好，但要备案和花钱

这篇测试文的目的就是先把链路跑通，选哪个托管反而不是重点。
